# Руководство по Synology Container Manager

[English](synology-container-manager.md) | [Español](synology-container-manager.es.md) | [Français](synology-container-manager.fr.md) | [Nederlands](synology-container-manager.nl.md) | [Português](synology-container-manager.pt.md) | [Русский](synology-container-manager.ru.md) | [简体中文](synology-container-manager.zh-CN.md) | [日本語](synology-container-manager.ja.md) | [한국어](synology-container-manager.ko.md) | [Bahasa Indonesia](synology-container-manager.id.md) | [Bahasa Melayu](synology-container-manager.ms.md)

Это руководство устанавливает бесплатный сервер Docker и веб-интерфейс через Container Manager. Для отдельно протестированного нативного пакета DSM см. [руководство по пакету Synology](synology-package.ru.md).

## Требования

- DSM 7 с Container Manager
- 64-разрядная модель Intel/AMD или ARM64, поддерживаемая опубликованным образом
- Разрешение на создание общих папок и проектов Container Manager

## 1. Создание папок

В File Station создайте:

```text
docker/bibliofuse/config
docker/bibliofuse/cache
```

Проект подключает DSM `/volume1` в режиме только для чтения. В настройках отображаются фактические общие папки, которые может читать настроенная учётная запись DSM; ни одна из них не подключается автоматически.

## 2. Выбор пользователя контейнера

Контейнер должен записывать конфигурацию/кеш и читать библиотеку. Используйте числовые UID и GID специальной учётной записи DSM с этими правами. По SSH:

```sh
id <username>
```

Значения по умолчанию `1026:100` приведены только как примеры и могут не соответствовать вашему NAS.

## 3. Создание проекта

1. Скачайте `synology/compose.yaml`.
2. Откройте Container Manager → Project → Create.
3. Выберите имя проекта, например `bibliofuse`.
4. Загрузите или вставьте файл Compose.
5. Задайте:
   - `CONFIG_PATH`, например `/volume1/docker/bibliofuse/config`
   - `CACHE_PATH`, например `/volume1/docker/bibliofuse/cache`
   - `PUID` и `PGID`
   - `BF_TIME_ZONE`, например `Asia/Kuala_Lumpur`
6. Соберите/запустите проект.

## 4. Первая настройка

Откройте:

```text
http://<nas-ip>:7343
```

Создайте пароль администратора длиной не менее 12 символов. В настройках выберите **Attach library**, выберите отображаемую общую папку DSM или подпапку с книгами, затем выберите Refresh. Не нужно вводить путь DSM или контейнера. Средство выбора исключает недоступные для чтения общие папки согласно выбранным UID/GID контейнера.

Корни можно изменить, отключить или удалить. Отключение сохраняет данные каталога. Удаление очищает каталог BiblioFuse, метаданные и прогресс чтения этого корня, не удаляя файлы или папки; удаление последнего корня оставляет корректную пустую библиотеку.

## 5. Чтение и обновление

Refresh проверяет всё подключённое дерево и индексирует новые, изменённые, переименованные или удалённые книги. Автоматическое обновление по умолчанию отключено; в настройках можно запланировать ежедневное или еженедельное обновление.

Непрерывный режим комиксов загружает страницы постепенно. На DS923+ или похожем NAS для не кешированных страниц архивов всё ещё может быть небольшая задержка загрузки. Mac или ПК обычно обеспечит более плавную нативную потоковую передачу, поскольку его процессор может быстрее распаковывать и подготавливать страницы.

## 6. Резервное копирование и обновление

- Включите папку конфигурации в Hyper Backup.
- Кеш можно исключить.
- Перед обновлением скачайте резервную копию BiblioFuse в настройках.
- Сохраните предыдущую резервную копию конфигурации, поскольку миграции базы данных могут поддерживать только движение вперёд.
- Загрузите новый образ и пересоздайте проект без изменения сопоставлений папок.

Никогда не выбирайте вариант удаления, который удаляет подключённые папки конфигурации или библиотеки.

Для сброса Container Manager к заводским настройкам остановите проект, создайте резервные копии и переименуйте настроенные папки конфигурации и кеша, создайте новые пустые папки с исходными именами и разрешениями, затем перезапустите. Никогда не включайте папку библиотеки в эту очистку.

## 7. Сетевая граница

- `7343`: бесплатный интерфейс в браузере в доверенной локальной сети
- `7342`: закреплённый HTTPS API нативных клиентов, обнаруживаемый в локальном Wi-Fi через Bonjour
- `7341`: не публиковать

Container Manager и нативный `.spk` выполняют сопряжение с выпущенными приложениями iOS/visionOS в локальном Wi-Fi через Bonjour. Нативная потоковая передача по-прежнему ограничена Premium-возможностью нативного приложения; Docker не предоставляет ручной/маршрут Tailscale для нативных клиентов.

Не запускайте этот проект Container Manager рядом с нативным пакетом BiblioFuse Synology на одном NAS. Обе службы используют порты `7342` и `7343`; выберите один способ установки.
