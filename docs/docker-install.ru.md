# Установка и работа Docker

## Язык браузера

После настройки откройте Настройки и выберите **Язык**. Браузер может следовать системному языку или использовать английский, испанский, французский, нидерландский, португальский, русский, упрощённый китайский, японский, корейский, индонезийский или малайский. Выбор хранится только в этом браузере и не влияет на контейнер или метаданные библиотеки.

## 1. Выберите папки

| Назначение | Путь контейнера | Требуемый доступ | Резервная копия |
| --- | --- | --- | --- |
| Учётная запись, идентичность, каталог и настройки | `/config` | Чтение/запись | Да |
| Подготовленные страницы и миниатюры | `/cache` | Чтение/запись | Нет |
| Ваша библиотека книг | `/library` | Только чтение | Отдельно |

Пути контейнера постоянны. `CONFIG_PATH`, `CACHE_PATH` и `LIBRARY_PATH` выбирают реальные папки хоста. Docker сам не находит библиотеку: смонтируйте папку до первого запуска, затем выберите папку для подключения в Настройках.

## 2. Настройте Compose

Скачайте файлы из `docker/`, скопируйте `.env.example` в `.env` и отредактируйте `.env`. Для сервера используйте абсолютные пути. В Linux получите числовые ID пользователя и группы:

```sh
id
```

Укажите в `PUID` и `PGID` учётную запись, которая может писать в config/cache и читать библиотеку. BiblioFuse работает без root-привилегий.

## 3. Запустите и проверьте

```sh
docker compose pull
docker compose up -d
docker compose ps
docker compose logs --tail=100 bibliofuse
```

Откройте `http://<server-ip>:7343`. Создайте администратора, затем выберите **Подключить библиотеку**. Селектор показывает настроенное монтирование **Библиотека** и подпапки, но в новой установке нет подключённого корня, пока вы не выберете его и не обновите.

Не запускайте эту Docker-службу с сетью хоста рядом с нативным пакетом Synology на одном NAS: оба используют нативный HTTPS `7342` и браузерный интерфейс `7343`. Первое обновление проходит по всей библиотеке; последующие проверяют дерево, но используют неизменённые метаданные архивов.

## 4. Добавьте другую папку библиотеки

Каждый корень должен ссылаться на путь внутри контейнера. Сначала добавьте в `compose.yaml` новое монтирование только для чтения:

```yaml
volumes:
  - "/srv/books:/library:ro"
  - "/srv/manga:/books/manga:ro"
environment:
  BF_LIBRARY_BROWSE_ROOTS: >-
    [{"name":"Library","path":"/library"},{"name":"Manga","path":"/books/manga"}]
```

Пересоздайте контейнер и выберите Настройки → Подключить библиотеку → **Manga**. Не вводите в веб-интерфейсе ни `/books/manga`, ни путь хоста `/srv/manga`. **Изменить** сохраняет идентичность каталога, если смонтированная папка переименована. **Отключить** сохраняет данные каталога. **Отсоединить** работает и для последнего корня и удаляет его каталог, метаданные и прогресс, не удаляя файлы или папки.

## 5. Расписание, обновление и удаление

Настройки предлагают Отключено, Ежедневно и Еженедельно; время задаётся с шагом 30 минут. Укажите действительную зону IANA в `BF_TIME_ZONE`, например `Asia/Kuala_Lumpur`.

Для контролируемого развёртывания используйте нумерованный тег образа, создайте копию `/config`, затем:

```sh
docker compose pull
docker compose up -d
docker image prune
```

`docker image prune` необязателен и удаляет неиспользуемые образы, а не книги. Чтобы остановить или удалить контейнер:

```sh
docker compose down
```

Это не удаляет папки хоста config, cache или library. Для явного заводского сброса остановите Compose, сохраните папки `CONFIG_PATH` и `CACHE_PATH`, переименуйте их как сохраняемые копии, создайте новые пустые папки с теми же именами и правами и снова выполните `docker compose up -d`. Никогда не переименовывайте, не очищайте и не удаляйте `LIBRARY_PATH`: оно смонтировано только для чтения.

## Внешний доступ и диагностика

Не перенаправляйте порт `7343` напрямую с маршрутизатора. Используйте доверенный HTTPS reverse proxy с аутентификацией и действительным сертификатом либо LAN-адрес через собственную VPN/Tailscale-сеть. Адрес Tailscale с `:7343` даёт браузерный доступ и не добавляет Docker-сопряжение выпущенным приложениям iOS/visionOS.

Если селектор пуст, проверьте `LIBRARY_PATH`, монтирование `/library:ro` командой `docker compose config`, доступ `PUID:PGID` и пересоздайте контейнер после изменения монтирования. При отказе в доступе исправьте права или `PUID`/`PGID`, а не запускайте контейнер от root. Паузы на холодных страницах — работа CPU/диска; постоянный кэш улучшает повторное чтение. При постоянных перезапусках выполните:

```sh
docker compose ps
docker compose logs --tail=200 bibliofuse
```

Проверьте неверные пути монтирования, права записи config/cache, конфликты портов и повреждённый или неполный `.env`. Восстановления по email нет: пересоздание одного контейнера не сбрасывает пароль, так как проверка находится в `/config`; заводской сброс допустим только при согласии потерять учётную запись, идентичность, каталог и настройки BiblioFuse. Библиотека останется нетронутой.
