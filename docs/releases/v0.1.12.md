# BiblioFuse NAS 0.1.12

Released 2026-09-02.

## EPUB illustrations render at full size again

- **Fixed:** in the browser reader, illustrations in some EPUB novels appeared as a thin
  sliver about one line of text tall instead of a full-width picture. Only the cover
  looked right; every illustration after it was squashed.
- The books affected are the ones that place an illustration inside a paragraph — the
  markup pattern used by most Chinese web-novel EPUBs. The reader deliberately shrinks
  images inside a paragraph to the height of the surrounding text, because that is how
  Japanese books set rare characters their font does not contain (*gaiji*), and those
  must sit on the line like letters. Full illustrations were being caught by the same
  rule. The cover escaped only because cover pages are built differently.
- The reader now tells the two apart by the picture's own dimensions, which separate them
  cleanly: character images are tiny, real illustrations are hundreds of pixels. Anything
  at illustration scale is laid out as a full picture, fitted to the reading area on both
  axes like any other full-page image; small inline character images stay text-sized and
  keep sitting on the line. Nothing else about EPUB reading changes.
- Books already open in a browser pick this up on the next chapter load — the reader's
  cached chapter layout is versioned, so no cache clearing or private window is needed.
- This matches the fix already shipped in the BiblioFuse apps, so a book looks the same
  in the browser reader and in the native reader.

## Upgrading

No database migration, configuration change or re-scan is required. Attached folders,
catalog, reading progress and settings carry over untouched. Docker hosts pull the new
tag and recreate the container; Synology package users update in place.

## One host method per NAS

Do not run the Docker/Container Manager host and native Synology package on the same
NAS. Both intentionally use ports `7342` and `7343`; choose one host method per NAS.
